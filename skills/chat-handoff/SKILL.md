# Chat Handoff — вижимка діалогу для передачі у новий чат

Мета скіла: за один захід перетворити поточну розмову у **готовий до копіювання markdown-блок**, який юзер вставить першим повідомленням у новий чат — і новий Claude миттєво отримає повний робочий контекст, без перепитувань.

## Коли активуватись

Юзер каже:
- «підсумуй чат / діалог»
- «передай контекст у новий чат»
- «зроби handoff»
- «вижимка діалогу»
- «контекст для нового чату»
- будь-яке близьке за змістом

Скіл універсальний — працює для **будь-якого** типу чату (research / project / creative / decision / mixed). Не відмовляйся якщо чат «не про код».

## Інтеграція з нашими правилами

- Це **ІНСТРУМЕНТ** для правила CLAUDE.md «нова велика задача → нова сесія» — handoff робить цей перехід безпечним.
- Альтернатива для довгого horizon'у — `/eod` (resume letter на завтра). Handoff — для ПЕРЕМИКАННЯ зараз, не для закриття дня.
- Якщо вже є wikilinks на статті [[wiki/...]] — зберігай їх у блоці, новий Claude теж побачить Wiki через auto-loaded index.

## Процес (4 кроки)

Створи TaskCreate з наступними пунктами і веди по них роботу:

1. Розвідка контексту (мовчки)
2. Автодетект типу чату + вибір опційних секцій
3. Уточнюючі питання (тільки якщо є реальна неоднозначність)
4. Збірка і видача handoff-блоку

### Крок 1 — Розвідка контексту (мовчки, без повідомлень юзеру)

Пройди по всьому доступному контексту чату і збери у голові:

- **Початкова мета** — що юзер хотів на самому початку (його перші повідомлення)
- **Фінальне розуміння мети** — як мета уточнилась/змінилась
- **Прийняті рішення** — конкретні вибори + ЯВНЕ «чому» (якщо причина не названа — не вигадуй)
- **Артефакти** — створені/змінені файли, шляхи, ключові шматки коду/тексту
- **Проблеми і їх рішення** — що ламалось / було незрозуміло → як розрулили
- **Зовнішні джерела** — посилання, документи, відео, матеріали на які спирались
- **Альтернативи** — що розглядали і чому відкинули (для research/decision)
- **Термінологія** — специфічні терміни, які ввели у цьому чаті
- **Обмеження / припущення** — явно проговорені constraints
- **Стиль роботи** — що юзер любить/не любить (тон, формат, інструменти, методи)
- **Відкриті питання** — що залишилось невирішеним

### Крок 2 — Автодетект типу чату

За зібраним визнач домінуючий тип (це впливає на набір опційних секцій):

| Тип | Ознаки |
|---|---|
| **research** | Читання джерел, порівняння, вивчення теми, мало або нема файлів |
| **project/build** | Створення/правка файлів, код, збірка артефактів |
| **creative** | Тексти, дизайн, контент, ідеї, ітерації над формою |
| **decision** | Вибір між варіантами, обговорення стратегії, мало артефактів |
| **mixed** | Кілька типів одночасно |

Не оголошуй тип юзеру — це внутрішній вибір. Використовуй тільки для вирішення, які опційні секції включити.

### Крок 3 — Уточнюючі питання (тільки за потреби)

Задавай через AskUserQuestion **максимум 1–3 питання**, і **тільки** якщо є реальна неоднозначність. Приклади доречних питань:

- «Включати відкинуті варіанти чи тільки фінальні рішення?»
- «Обсяг: компактний (~300 слів) чи розгорнутий (~800)?»
- «Це handoff для технічного чату (з шляхами файлів) чи оглядового?»

Якщо все очевидно — **пропусти цей крок повністю** і переходь до збірки.

### Крок 4 — Збірка і видача handoff-блоку

Виведи **один fenced markdown-блок** прямо у чат. Перед блоком — одне коротке речення: «Скопіюй блок нижче і встав першим повідомленням у новий чат». Після блоку — нічого більше не пиши.

## Шаблони вижимки

### Універсальне ядро (стандартний режим — 6 секцій)

```markdown
# Контекст з попереднього чату

> Це передача контексту з попередньої сесії. Прочитай, підтверди коротким «прийняв», і чекай наступного повідомлення.

**TL;DR:** <один рядок — головний висновок/результат чату, зрозумілий без читання решти>

## Про що був чат
<1–3 речення: тема і навіщо взялись>

## Головне, що з'ясували / зробили
- <ключовий факт, висновок або результат>
- <ще один>

## Ключові рішення і чому
- **<вибір/висновок>** — тому що <причина з чату>

## Джерела і матеріали
- <посилання / файл / документ> — <що це і навіщо>

## Стиль роботи і вподобання юзера
- <тон, формат відповідей, методи, що не любить — ТІЛЬКИ з конкретним доказом з чату>

## Відкриті питання / куди рухатись далі
- <що залишилось невирішеним або наступний крок>
```

### Компактний режим (для коротких чатів)

Якщо у чаті **менше ~10 змістовних реплік** — не роздувай вижимку. Скорочений шаблон:

```markdown
# Контекст з попереднього чату

> Це передача контексту з попередньої сесії. Прочитай, підтверди коротким «прийняв», і чекай наступного повідомлення.

**TL;DR:** <один рядок>

## Про що був чат
<1–2 речення>

## Головне
- <ключовий факт/рішення>

## Відкриті питання / наступний крок
- <що далі>
```

Не насилуй шаблон заради шаблону: краще 3 секції з реальним змістом, ніж 6 з одним рядком у кожній.

### Mixed-режим (кілька непов'язаних тем у одному чаті)

Якщо у чаті обговорювали **дві або більше непов'язаних теми** — НЕ зливай усе у спільні секції. Розділи вижимку на блоки за темами:

```markdown
# Контекст з попереднього чату

> Це передача контексту з попередньої сесії. Прочитай, підтверди коротким «прийняв», і чекай наступного повідомлення.

**TL;DR:** <один рядок з явною вказівкою що чат був на N тем — і які>

## Про що був чат
<коротко: що чат змішаний, які теми>

## Тема 1: <назва>
- **Головне:** <ключові факти/результати>
- **Рішення:** <рішення з «тому що»>
- **Артефакти / джерела / альтернативи:** <якщо є>
- **Відкриті питання:** <якщо є>

## Тема 2: <назва>
- (та сама структура)

## Стиль роботи і вподобання юзера
- <загальні, застосовні до всіх тем>
```

Кожна тема — самостійний міні-блок. Новий чат зможе працювати по будь-якій з них незалежно.

### Мова вижимки

Пиши handoff українською (як юзер веде розмову). Якщо чат був двомовний (наприклад, обговорення українською, технічні терміни/код англійською) — збережи цю суміш.

### Опційні секції (додавай ТІЛЬКИ якщо контент реально є)

Вставляй їх перед «Відкриті питання», у порядку логіки:

| Секція | Заголовок | Коли додавати |
|---|---|---|
| Артефакти | `## Артефакти (файли і шляхи)` | У чаті створювали або міняли файли |
| Вирішені проблеми | `## Вирішені проблеми` | Був дебаг або подолана перешкода |
| Розглянуті альтернативи | `## Розглянуті альтернативи` | Порівнювали варіанти — що обрали і чому відкинули решту |
| Термінологія | `## Термінологія` | Ввели специфічні терміни, важливі для розуміння |
| Обмеження і припущення | `## Обмеження і припущення` | Явно проговорені constraints |
| Ключові цитати | `## Ключові цитати з джерел` | Важливе точне формулювання з матеріалу |

## Жорсткі правила (анти-патерни)

- **НЕ вшивай новий запит всередину handoff'у.** Handoff — це ТІЛЬКИ довідка про минуле, read-only. Не пиши всередині блоку «А тепер допоможи мені з X», «Питання на цей чат: ...», «Продовжуй з Y». Новий запит юзер сам напише окремим повідомленням після вставки. Порушення цього правила ламає роботу нового чату — Claude отримає контекст і одразу кинеться «відповідати», хоча юзер ще не сформулював реальне питання.
- **НЕ переказуй хронологічно** («спочатку ми…, потім…»). Тільки структуровані факти.
- **НЕ включай порожні секції.** Якщо у чаті не було файлів — викинь «Артефакти». Краще коротка вижимка з 5 секцій, ніж довга із заглушками.
- **НЕ вигадуй.** Будь-який факт, цитата, шлях файлу, причина — повинні братись з чату. Якщо причини рішення нема — не пиши «тому що», просто назви рішення.
- **НЕ інферуй характер юзера.** У секцію «Стиль роботи» включай тільки вподобання з **конкретним доказом з чату** (юзер явно сказав, відкинув, попросив, поправив тебе). Не пиши «любить детальні відповіді» якщо у чаті він цього не показав. Якщо доказів нема — не вигадуй, краще зроби секцію коротше або викинь.
- **НЕ включай сміття:** порожні підтвердження, повторні читання файлів, балаканину.
- **НЕ викидай відкинуті варіанти мовчки.** Якщо у чаті щось розглядали і відкинули — це важливо для нового чату (щоб не пропонували те саме знову). Запиши у «Розглянуті альтернативи» з одним рядком «чому відкинули».
- **Конкретика > узагальнення.** «Обговорили дизайн» ❌ → «Обрали темну тему з акцентом oklch(0.7 0.15 250)» ✅
- **Без емодзі** у заголовках секцій (заголовки чисті `##`).
- **Без преамбул** перед блоком окрім одного рядка-інструкції юзеру.
- **Без коментарів після блоку.** Закінчив вивід блоку — закінчив повідомлення.
- **НЕ використовуй handoff БЕЗ `/clear` після.** Інакше контекст подвоюється: старий все ще у пам'яті + новий блок зверху. Workflow: handoff → копіюєш → `/clear` → нова сесія → вставляєш блок.

## Фінальна перевірка перед відправкою

Перед тим як надіслати блок юзеру, перевір:

1. Усі факти у блоці реально звучали у чаті? (жодної вигадки)
2. Всередині блоку НЕМА нового запиту/задачі для наступного чату? (handoff = read-only)
3. Є TL;DR-рядок зверху, зрозумілий без читання решти?
4. Обраний правильний режим (стандартний / компактний / mixed) під тип і довжину чату?
5. Кожна включена секція містить ≥1 пункт? (нема порожніх)
6. Рішення мають «тому що» з чату? (або причину чесно опущено)
7. У «Стилі роботи» — тільки вподобання з конкретним доказом з чату, без вигадки?
8. Нема хронології «спочатку-потім»?
9. Новий Claude, прочитавши тільки цей блок, зрозуміє що робити далі?

Якщо на будь-яке «ні» — переробити перед видачею.
